# 수동 검증 항목

자동 테스트는 좌표 변환·문단 구성·실제 Vision OCR·동일 이미지 생략을 검증한다.
아래 항목은 화면 기록 권한이 있는 실제 Mac에서 확인해야 한다.

## 현재 검증 상태

- 자동 테스트 46개 통과: core 18개, 앱 28개. 직접 선택의 강조 영역이 클릭을 통과시키는 완전 투명 픽셀로 바뀌지 않는 회귀 테스트를 포함한다.
- 2026-11-03 실제 화면에서 창 직접 클릭 → OCR, 겹친 두 창의 각각 선택과 앞쪽 창 선택, 창 내부 드래그 영역의 OCR·번역, 선택 클릭이 대상 버튼에 전달되지 않음, 취소 후 기존 대상 유지, 목록 닫기와 직접 선택↔목록 전환을 확인했다.
- 일반 창뿐 아니라 떠 있는 앱 창도 선택 대상에 포함했다. 선택 중 앱을 다시 열어도 결과 창이 나타나 선택을 방해하지 않도록 수정하고 확인했다.
- 릴리스 빌드, 앱 번들 생성·고정 자체 서명 검증, 앱 실행 확인.
- 초기 권한 안내, 설정 화면, 시스템 번역 언어 목록, 결과 창 기본 상태 확인.
- 해제 단축키 기본 미지정, 단축키 입력 및 Escape 등록 거부 확인.
- 저장된 서명과 현재 빌드의 불일치를 실제 TCC 로그로 확인했다. LineLens의 화면 기록 승인만 초기화하고 현재 앱을 재승인한 뒤, 두 번의 앱 실행에서 ScreenCaptureKit 접근 성공을 확인했다.
- 소스 변경 없는 반복 빌드에서 서명 해시·실행 파일 SHA-256·inode 유지 확인.
- 프로그램 창의 지속 캡처 → 실제 Vision OCR → Apple 번역을 테스트 창에서 확인했다. 정지 상태 및 배경 표시만 변경한 경우 결과 행·번역을 유지했고, `Page 124` → `Page 125` 변경 시 해당 문단만 새로 인식·번역했다.
- 숫자 변경 번역 검증은 원문 언어를 영어로 지정해 수행했다. 짧은 문구를 자동 언어 감지로 번역하면 식별 실패가 발생할 수 있다. 테스트 후 기존 Antigravity 대상과 원문 언어 자동 감지를 복원했다.
- 창 직접 선택 검증은 `scripts/qa-fixture.swift --two-windows`의 일반·보조 창으로 수행했다. 창 내부 `Page 123` 영역에서 원문 한 문단과 `페이지 123` 번역만 표시되는 것을 확인했다. 짧은 제목·기호가 섞인 전체 창의 자동 번역은 기존 언어 식별 한계가 남아 있다.
- 화면 고정 영역과 오버레이의 전체 흐름은 별도 검증이 필요하다.
- 번역 모델 다운로드·오프라인 번역, 다중 모니터·전체 화면·Spaces 동작은 미검증이다.

## 실행 및 권한

- `./scripts/build-app.sh`로 빌드하고 `open dist/LineLens.app`으로 실행한다.
- 메뉴 막대에 LineLens 아이콘이 표시되는지 확인한다.
- 권한이 없는 상태에서 안내 창이 표시되고, 사용자 버튼으로 권한을 요청하는지 확인한다.
- 시스템 설정에서 화면 기록을 허용한다. 적용되지 않으면 앱을 종료하고 재실행한다.
- 권한을 다시 끈 경우 오류가 표시되고 인식 대상을 다시 선택할 수 있는지 확인한다.
- 권한 목록에서 LineLens가 켜져 있는데 안내가 남으면 ‘권한 다시 확인’으로 실제 접근을 확인한다.
- 재빌드 후 기존 승인이 적용되지 않으면 ‘권한 연결 초기화’ → ‘앱 다시 실행’ → 현재 앱 허용 순서로 복구한다.
- 단순 재등록으로 복구되지 않으면 `./scripts/reset-screen-permission.sh --relaunch`로 LineLens의 화면 기록 승인 연결만 초기화한다.
- 초기화 후 재실행 전에는 재확인이 차단되어 오래된 거부 상태를 다시 만들지 않는지 확인한다.
- 소스 변경 없이 빌드를 반복했을 때 앱의 서명 해시와 실행 파일 inode가 유지되는지 확인한다.

## 고정 영역

- 메뉴 또는 기본 단축키 `Control + Option + L`로 영역을 선택한다.
- 마우스를 놓은 뒤에도 영역 테두리가 남고, 그 안의 글자가 결과 창에 표시되는지 확인한다.
- 다른 앱의 Escape 조작이 유지되고, Escape로 인식이 해제되지 않는지 확인한다.
- 선택 도중 메뉴의 ‘선택 취소’, 인식 중 메뉴의 ‘인식 해제’가 동작하는지 확인한다.
- 영역 안에서 클릭·스크롤이 대상 앱으로 전달되는지 확인한다.
- ‘영역 이동·크기 변경’으로 이동 및 오른쪽 아래 크기 조절을 확인한다.
- 자동 갱신 끄기, 수동 새로고침, 일시정지·재개를 확인한다.
- Retina·외부 모니터와 주 모니터의 위·왼쪽에 배치한 모니터에서도 좌표를 확인한다.
- 화면 영역 드래그는 한 모니터 안에서 수행한다.

## 프로그램 창

- 결과 창의 ‘창 선택’ 또는 메뉴의 ‘프로그램 창 직접 선택’이 목록 대신 화면 선택을 여는지 확인한다.
- 마우스를 올린 창에 테두리와 제목이 표시되고 한 번 클릭하면 해당 창의 OCR이 시작되는지 확인한다.
- 겹친 창에서는 클릭한 위치의 앞쪽 창이 선택되고, 선택 클릭이 대상 앱의 버튼을 실행하지 않는지 확인한다.
- 창 내부에 마우스를 1초 이상 올려 강조된 뒤 클릭해도 바로 선택이 확정되는지 확인한다. 빠르게 이동해 즉시 클릭하는 경우뿐 아니라 강조가 그려진 뒤의 클릭도 검증한다.
- 상단에서 ‘창 내부 영역’을 선택하고 창을 클릭한 뒤 드래그로 일부 영역을 지정한다.
- 화면 위 ‘취소’와 메뉴의 ‘선택 취소’가 오버레이를 닫고 기존 대상을 유지하는지 확인한다. 빈 바탕화면 클릭으로 임의의 창이 선택되지 않아야 한다.
- 선택 화면의 ‘목록에서 선택’, 목록 화면의 ‘화면에서 선택’ 전환과 목록 닫기 버튼·창 닫기를 확인한다. 닫은 뒤 새로고침이 다시 동작해야 한다.
- 선택 중 Escape가 전역 취소로 동작하지 않는지 확인한다. 외부 디스플레이와 Spaces 전환은 별도로 확인한다.
- 창 목록 검색 후 전체 창 또는 일부 영역을 선택한다.
- 창을 이동·크기 변경했을 때 표시가 따라가고 OCR이 갱신되는지 확인한다.
- 다른 앱을 앞으로 가져오거나 대상 창을 최소화했을 때 번역 표시가 숨겨지는지 확인한다.
- 창을 다시 앞으로 가져왔을 때 복구되고, 닫힌 창은 메뉴에서 해제할 수 있는지 확인한다.
- 전체 화면 및 Spaces 전환 시 다른 작업 공간에 번역이 잘못 표시되지 않는지 확인한다.

## 번역 및 설정

- 지원되는 원문·목표 언어를 지정하고 자동 번역을 켠다.
- 언어 모델이 없으면 결과 창에서 시스템 다운로드 안내가 표시되는지 확인한다.
- 설치 후 네트워크를 끈 상태에서도 OCR·번역이 동작하는지 확인한다.
- 번역 실패 시 원문이 남고, 언어 변경 또는 재번역으로 재시도할 수 있는지 확인한다.
- 결과 창·원문 위치·둘 다, 원문 덮기·원문 아래 표시를 확인한다.
- 원문 수정·재번역, 원문·번역 복사, 결과 창 고정을 확인한다.
- 해제 단축키가 기본 미지정인지 확인하고, 사용자 지정과 제거·재실행 후 저장을 확인한다.
- 단축키 충돌 시 안내가 표시되고 메뉴 동작은 유지되는지 확인한다.
- 짧은 UI 문구의 자동 언어 식별이 실패하면 원문 언어를 직접 지정한다. 번역 실패 중에도 OCR 원문과 다른 문단의 기존 번역이 유지되는지 확인한다.

## 변경 감지 및 깜빡임

- `scripts/qa-fixture.swift`의 테스트 창처럼 고정된 글자가 있는 창을 선택한다.
- 정지 상태로 여러 갱신 주기를 기다린다. 결과의 문단 ID·원문·번역·갱신 시각과 처리 표시가 반복해서 바뀌지 않아야 한다.
- 배경만 바꾼다. 글자가 같으면 기존 번역과 결과 행을 유지해야 한다.
- 숫자 한 글자를 바꾼다. 해당 문단의 원문과 번역만 갱신되어야 한다.
- 다른 앱을 사용하는 중에도 선택한 프로그램 창의 글자 변경이 결과 창에 반영되는지 확인한다.
- 자동 모드의 Capture 로그에서 `Live capture session started`가 갱신 주기마다 반복되지 않아야 한다. 영역 변경·크기 변경·일시정지·해제 때는 재설정될 수 있다.

## 알려진 범위

- 원문 배경 복원, 캡처 기록 저장, 이미지 파일 입력은 현재 구현 범위에 포함하지 않는다.
- 화면 위 번역 상자는 기본 줄바꿈·글자 크기를 조정한다. 복잡한 배치에서 상자 간 겹침을 완전히 해결하지는 않는다.
- 혼합 언어·세로쓰기·복잡한 다단 문서는 인식 순서 및 번역 품질을 별도로 확인해야 한다.
- 개발·배포본 모두 고정 자체 서명을 사용한다. Developer ID 서명·공증은 포함하지 않는다.

## Sparkle 업데이트 (2026-11-03)

- Sparkle 2.10.1 포함 후 기존 자동 테스트 22개 통과, Apple Silicon·Intel 통합 빌드와 모든 아키텍처 코드 서명 검증 성공.
- 0.1.1 (build 2)의 코드 서명 요구조건을 0.1.2 (build 3)이 만족함을 확인했다. 앱 실행 시 화면 기록 재승인은 요청하지 않았다.
- 실제 설정에서 버전 표시, ‘업데이트 확인…’ 활성 상태, 자동 확인 켜기·끄기, 앱 메뉴 항목을 확인했다. 자동 확인은 끄기로 복원했다.
- 수동 확인 시 Sparkle 오류 창이 정상 표시되었으며, 로그에서 원인이 미게시 공개 피드의 HTTP 404임을 확인했다.
- 프레임워크의 중첩 서명을 포함한 반복 빌드에서도 변경 없는 기존 앱 번들과 inode를 유지했다.
- 잘못된 Ed25519 공개 키는 빌드 전 검증에서 거부했다.
- 사용자 키체인 인증 후 공식 도구로 ZIP·피드 서명을 생성·검증했다. ZIP을 같은 크기로 변조한 경우와 피드 제목을 변조한 경우 각각 서명 검증이 실패했다.
- 임시 로컬 HTTP 피드와 테스트 앱 복사본으로 새 버전 알림 → 다운로드 → 설치 → 자동 재실행을 확인했다. 배포용 소스·앱의 피드는 공개 GitHub HTTPS 주소를 유지한다. 로컬 테스트의 0.1.3~0.1.6은 배포 버전이 아니다.
- 같은 실행 파일에서 Info.plist 버전만 바꾼 테스트에서 자동 재실행 직후 이전 버전이 표시되는 현상을 확인했다. 빌드 스크립트가 최종 Info.plist를 실행 파일의 `__TEXT,__info_plist`에도 포함하도록 보완했다. 이후 코드 변경 없는 버전·빌드 번호 갱신에서도 자동 재실행 직후 새 버전 표시와 다음 업데이트 확인이 정상 동작했다.
- 업데이트 설치 후 ScreenCaptureKit 접근 성공 로그를 확인했다. 화면 기록 재승인이나 권한 초기화는 하지 않았다. 자동 번역·목표 언어·갱신 간격·결과 표시 설정도 유지했다.
- 공개 HTTPS 서버에서의 업데이트 및 다른 Mac·Intel 하드웨어의 실제 업데이트는 별도 검증이 필요하다.

## 직접 선택 클릭 확정 회귀 (2026-11-03)

- 강조된 창의 내부를 알파 0으로 지우면서 클릭이 뒤쪽 프로그램으로 통과할 수 있는 문제를 수정했다. 내부에는 2%의 옅은 검정색을 유지해 선택 창이 클릭을 받게 한다.
- 수정 전 실제 렌더링 테스트에서 강조 영역의 알파가 0으로 나와 실패했으며, 수정 후 일반 좌표·음수 화면 원점 두 경우 모두 통과했다.
- 진단 중 WindowServer의 마우스 대상이 뒤쪽 앱에서 선택 패널로 바뀌고 선택 완료 콜백이 실행되는 것을 확인했다. 진단용 코드는 최종 소스에서 제거했다.


## 캡처 이미지 번역 오버레이

- 설정에서 자동 번역을 켜고, 결과 표시 ‘번역 화면’과 화면 위 번역 ‘이미지 속 글자 바꾸기’를 선택한다. 기존 저장 설정은 새 기본값으로 강제 변경하지 않는다.
- 밝은/어두운 단색 UI를 선택하고, 영어 글자만 번역되며 아이콘·버튼 배경·구분선이 유지되는지 확인한다.
- 번역된 버튼을 누르고 스크롤·드래그·키보드 입력을 해 원래 프로그램이 조작되는지 확인한다.
- `scripts/qa-fixture.swift`의 ‘Change last digit’로 숫자를 바꿔 기존 번역 화면이 유지되다가 새 숫자의 번역 화면으로 바로 교체되는지 확인한다.
- 메뉴·별도 팝업·다른 창이 대상 창 위에 열리면 원래 UI가 보이는지 확인한다. 전체 창의 상단 32pt는 번역하지 않는다.

### 오버레이 깜박임 회귀 확인

- 로딩 표시·영상·시계가 움직이거나 실제 글자가 바뀌어도 오버레이 창과 번역 조각을 전체 해제하지 않는지 확인한다. 배경 갱신은 실시간 화면 표시 설정을 따른다. 실시간 화면 표시를 끈 경우에는 번역 영역 밖으로 새 글자가 이동해도 이전 번역 화면을 유지해야 한다.
- 주기적인 OCR과 합성 갱신 중 번역문이 사라졌다가 다시 나타나지 않는지 확인한다.
- 실제 글자·숫자를 바꾸거나 스크롤하면 오버레이 창 자체를 숨겼다가 다시 띄우지 않고 문구별 번역을 갱신하는지 확인한다. 실시간 표시에서는 새 위치의 원문이 인식 전 잠시 보일 수 있다.
- 자동 갱신을 끈 상태에서는 글자와 배경이 바뀌어도 마지막 번역 화면이 유지되는지 확인한다.

- 일시적인 캡처 중단·OCR 실패 중에 마지막 번역을 유지하고 정상 프레임이 돌아오면 갱신되는지 확인한다.
- 창 크기를 바꾸는 동안 이전 번역 이미지가 확대·축소되어 유지되다가 새 레이아웃으로 교체되는지 확인한다.

### 클릭 반응 회귀 확인

- 번역된 버튼을 연속 클릭해 원본 기능이 실행되고 새 화면 레이아웃도 갱신되는지 확인한다.

- 긴 문단을 번역하는 중 클릭·스크롤로 화면을 바꿔 OCR과 화면 갱신이 계속되는지 확인한다.

## 인식·표시 성능 개선 확인 (2026-11-03)

- 두 문단 중 숫자 하나만 바꾸면 해당 영역만 OCR하고, 다른 문단의 번역 조각은 재사용하는지 자동 테스트로 확인한다. 문구 삭제·큰 화면 전환도 확인한다.

## 인식 결과 창의 언어 선택

- 번역 토글 옆 ‘언어’를 눌러 ‘인식 언어’와 ‘목표 언어’ 두 항목만 표시되는지 확인한다.
- 인식 언어를 영어로 고르면 설정 창의 OCR 언어는 en-US, 원문 언어는 en으로 함께 변경되어야 한다. 자동 감지는 두 항목 모두 auto로 전환한다.
- 한국어·일본어·중국어 간체/번체도 각 엔진의 지원 식별자로 올바르게 연결되는지 확인한다. 서로 다른 문자 체계를 바꾸어 매핑하지 않는다.
- 두 언어를 함께 바꿀 때는 설정을 한 번에 적용하고, 새 언어의 OCR이 필요한 경우 기존 언어로 읽은 문구를 새 원문 언어로 먼저 번역하지 않아야 한다.
- 설정 창에서 OCR 언어와 원문 언어를 다르게 지정한 경우 결과 창에는 ‘설정에서 개별 지정’으로 표시한다. 팝오버를 열기만 해서는 저장값이 바뀌지 않아야 한다. 인식 언어를 새로 고른 경우에만 함께 변경한다.
- 목표 언어 변경은 OCR·원문 언어에 영향을 주지 않고 현재 내용을 재번역해야 한다.
- 번역을 끈 상태와 인식 대상이 없는 상태에서도 언어를 미리 선택할 수 있어야 한다.
- 완료 버튼으로 팝오버를 닫고 다시 열거나 앱을 재실행해도 선택한 값이 유지되어야 한다.
- 결과 창의 최소 폭에서도 번역 토글·언어 버튼이 잘리지 않는지 확인한다.

검증 기록: 자동 테스트 67개(앱 47개·코어 20개)와 릴리스 빌드·고정 서명 검증을 통과했다. 영어·한국어·일본어·중국어 간체/번체 및 지역 변형의 매핑, 개별 설정 보존, 새 인식 전 이전 원문 재번역 방지를 확인했다. 실제 결과 창에서 두 항목만 표시되는 것과 자동 감지 선택 시 설정 창의 OCR·원문 언어가 함께 자동으로 바뀌는 것을 확인했다. 인식 언어는 검증 전의 영어로 복원했고 목표 한국어는 유지했다.
