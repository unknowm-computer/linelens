# 캡처 이미지 기반 번역 오버레이: 1차 구현과 후속 계획

작성일: 2026-11-02

구현일: 2026-11-03

상태: 모델을 추가하지 않는 1차 구현 완료. 아래 검토 내용을 기준으로 캡처 이미지 합성, 줄별 원문 제거, 번역문 배치, 화면 변화 감지와 입력 통과를 연결했다. 복잡한 배경의 인페인팅·이미지 복원 모델은 후속 검토 대상으로 남긴다. 스크롤 이동 추적과 전환 자연화는 아직 구현하지 않았으며 [별도 계획](scroll-overlay-smoothing.md)에 정리한다.

## 구현 내용

- `OverlayImageRenderer`는 줄별 주변 색과 글자색을 추정해 작은 번역 이미지 조각을 만든다. 변경 없는 조각은 캐시에서 재사용한다. `TranslationOverlayController`는 조각별 Core Animation 레이어를 유지하며, 라이브 표시에서 전체 화면을 CPU 이미지로 다시 합성하지 않는다.
- 번역문은 원래 텍스트 영역 안에서 글자 크기·줄바꿈을 조정한다. 최소 9pt에서도 넘치면 생략한다. 사진·무늬의 배경은 주변 단색으로 덮으며 인페인팅과 원본 폰트 복원은 포함하지 않는다.
- OCR은 64px 타일의 픽셀 변화를 찾고 이전 문단 범위까지 확장해 해당 영역만 다시 인식한다. 영역이 8개를 넘거나 면적이 화면의 45%를 넘으면 전체 OCR로 전환한다. 변경 없는 문단과 번역은 유지하며 삭제된 문구는 제거한다.
- OCR 모드는 빠름/정확을 선택하며 기본값은 빠름이다. 빠른 Vision의 지원 언어를 실행 환경에서 조회한다. 지정 언어가 미지원이거나 평균 신뢰도가 0.3 미만이면 정확 모드로 재시도한다. 빠른 결과가 비었을 때는 가벼운 텍스트 검출로 글자가 있는 영역만 정확 모드로 재시도해 빈 배경에서 불필요한 정확 OCR을 피한다. 각 영역의 모드는 독립적으로 선택한다. 빠른 인식이 정상 영어에도 0.5 신뢰도를 반환하는 것을 확인해 정확 모드의 신뢰도 기준을 그대로 적용하지 않는다. 자동 감지에서 비라틴 문자의 누락을 완전히 판별할 수는 없으며 한국어·일본어는 언어 지정 또는 정확 모드를 권장한다.
- 기본 ‘앱 텍스트 우선’은 접근성 권한을 허용한 프로그램 창에서 AX의 보이는 value/title과 위치를 읽는다. 비밀번호 필드와 화면 밖 항목, 중복 부모·자식 문구를 제외한다. 창을 안전하게 식별할 수 없거나 텍스트가 없거나 큰 이미지·캔버스가 있으면 OCR로 전환한다. 화면 영역 선택은 항상 OCR이다. 메시지별 60ms·전체 탐색 약 450ms·1,500노드 제한으로 앱 응답 지연을 제한하며, 미지원 창은 5초 뒤에 다시 AX를 시도한다. AX의 상자는 실제 글자보다 넓을 수 있어 설정에서 화면 OCR을 직접 선택할 수 있다.
- 번역 속도/품질 선택의 기본값은 속도 우선이다. macOS 26.4 이상에서는 Apple Translation의 lowLatency/highFidelity 전략을 명시하고 언어 목록·지원 확인·캐시도 선택한 전략에 맞춘다. 이전 OS에서는 품질 선택을 비활성화하고 시스템 기본 번역을 사용한다.
- 화면 표시는 OCR·번역과 분리한다. 기본 ‘실시간 화면 표시’는 ScreenCaptureKit IOSurface를 배경 레이어에 직접 전달해 클릭·스크롤·배경 변화를 먼저 보여 준다. 캡처는 최대 30fps로 요청하고, 픽셀 분석은 최대 5fps로 합친다. 마지막 변경 프레임이 분석에서 누락되지 않도록 뒤따르는 분석을 예약한다. 이 수치는 요청·제한 주기이며 실제 보장 속도가 아니다.
- 실시간 표시에서는 OCR 전 새 위치의 원문이 잠시 보이거나 이동한 글자 위에 이전 번역 조각이 잠시 남을 수 있다. 실시간 표시를 끄면 다음 OCR과 조각 생성이 끝날 때까지 이전 번역 화면을 유지해 원문 노출을 줄인다. 대신 클릭 결과의 표시가 늦어진다. 자동 갱신을 끄면 두 모드 모두 마지막 번역 화면을 유지한다.
- `ImageOverlaySession`이 캡처·인식·렌더링 버전을 관리한다. 현재 글자와 불일치하는 오래된 작업은 거부하며, 일시적 오류 중에는 마지막 표시를 유지한다. 빈 화면은 인식 완료 후 이전 번역 조각을 제거한다.
- 번역 배치 전체 완료를 기다리지 않고 새 레이아웃을 먼저 표시한다. 대기 문구는 …로 가리고 부분 응답을 약 100ms 간격으로 반영한다. 번역 중에도 OCR은 계속하고 새 문구는 다음 배치로 대기시킨다. 이미 목표 언어인 문구와 숫자·기호는 원문 그대로 확정한다.
- 입력은 `ignoresMouseEvents = true`로 아래 프로그램에 통과시킨다. 클릭·스크롤 뒤에는 220ms 후 새 인식도 요청한다. 다른 창·메뉴가 대상을 덮거나 대상이 최소화되면 숨긴다. 크기 변경 중에는 기존 레이어를 새 크기에 맞춰 표시하다가 새 인식으로 교체한다. 전체 창 상단 32pt는 원래 화면을 유지한다.
- 결과 창의 ‘언어’ 팝오버는 ‘인식 언어’와 ‘목표 언어’를 제공한다. 인식 언어 하나를 고르면 OCR 언어와 번역 원문 언어를 각 엔진의 식별자에 맞춰 한 번에 적용한다. 자동 감지는 두 값을 모두 자동으로 바꾼다. 설정 창에서는 개별 선택을 유지하며 서로 다르게 지정한 값은 팝오버를 열기만 해서는 변경하지 않는다.
- 새 설정 추가 시 저장된 언어·단축키·표시 설정을 보존한다. 명시적으로 해제한 단축키는 저장·복원 후에도 해제 상태로 남는다.

## 스크롤 전환의 남은 과제

사용자는 현재 반응속도와 스크롤 사용성은 개선되었다고 평가했다. 다만 배경이 먼저 움직이고 번역 조각의 좌표는 OCR 후 갱신되므로 중간에 어긋남과 잔상이 보일 수 있다. 다음 작업은 반응성을 유지하면서 기존 번역 조각을 실제 콘텐츠 이동에 맞춰 옮기고, 고정 영역과 스크롤 영역을 분리한 뒤 새 영역만 자연스럽게 교체하는 것이다. 이동 추적·영역 분리·페이드는 이번 1차 구현에 포함하지 않는다. 상세 단계와 검증 기준은 [스크롤 전환 개선 계획](scroll-overlay-smoothing.md)을 따른다.

## 검증 결과

- `swift test`: 67개 테스트 통과(앱 47개·코어 20개). 통합 인식 언어의 엔진별 코드 매핑, 중국어 문자 체계 구분, 개별 언어 설정 보존과 새 OCR 전 잘못된 언어의 재번역 방지도 확인했다. 변경 영역 OCR과 삭제된 글자 제거, 미지원 언어의 정확 모드 전환, 번역 조각 재사용, 실시간 배경 레이어와 고정 화면 모드, 접근성 후보의 범위·중복·보안 필드 제외, 번역 전략 전환, 기존 설정 마이그레이션을 추가 확인했다. 새 OCR 후 번역 대기 표시를 포함한 화면 갱신, 부분 번역 도착 시 갱신, 진행 중인 번역을 취소하지 않는 작업 대기, 빈 화면 전환, 네이티브 창의 표시 유지와 크기 변경, 오래된 OCR 거부와 리셋 이후 렌더링 취소를 확인했다. 밝은/어두운 배경 합성, 원문 영역 밖 픽셀 보존, Retina 크기, 긴 번역의 영역 제한, 화면 버전 무효화, 클릭 통과 설정과 기존 설정 복원을 확인했다.
- 새 릴리스 설정 화면에서 앱 텍스트 우선·빠른 OCR·속도 우선·실시간 표시 켜기 기본값과 품질 전환 후 복원을 확인했다. 접근성 권한 없음에서 자동 OCR 전환과 검증용 창의 Page 125 → 126 → 127 인식·번역 갱신을 확인했다. 권한 허용 후 일반 앱의 실제 AX 추출은 미검증이다.
- 설치된 영어·한국어 모델로 `Page 124` → `Page 125`의 연속 번역을 실제 Apple Translation 세션에서 확인했다. 이 테스트는 모델이 없는 환경에서는 다운로드하지 않고 건너뛴다.
- 네이티브 QA 창에서 버튼을 연속 클릭해 원문이 Page 123 → Page 124 → Page 125로 바뀌고, 결과 창에서도 페이지 124 → 페이지 125로 갱신되는 것을 확인했다. 클릭 통과와 네이티브 창 표시 유지는 별도 자동 테스트로 확인했다.
- 릴리스 앱 빌드와 기존 고정 인증서 서명 검증을 통과했다.
- 모든 앱의 메뉴·스크롤·드래그·키보드 조작, 장시간 성능, 디스플레이 배율 변경, 전체 화면·Spaces 전환은 추가 수동 검증 대상으로 남긴다.

이하 내용은 초기 검토 기록이다. 현재 동작은 위 구현 내용과 실시간 화면 표시 설정을 기준으로 한다.

## 배경과 목표

현재 결과 창은 원문과 번역문을 문단별로 확인하는 데 초점이 있다. 사용자는 이 구성이 단어 학습용 UI처럼 느껴져, 다른 프로그램을 사용하면서 내용을 이해하는 용도로는 불편하다고 설명했다.

사용자가 제안한 방식은 선택한 영역이나 프로그램 창의 캡처 이미지를 원래 화면 위에 겹쳐 표시하되, 인식한 원문만 번역문으로 바꾸는 것이다. 오버레이는 마우스 입력을 받지 않아 실제 클릭과 스크롤은 아래 프로그램에 전달한다.

대상은 설정 화면뿐 아니라 일반적인 앱 화면과 이미지도 포함한다. 다만 배경의 복잡도에 따라 원문 제거 품질과 처리 비용이 달라진다.

## 동작 구상

1. 선택한 화면 영역 또는 프로그램 창을 캡처한다.
2. OCR로 텍스트와 위치를 추출한다.
3. 인식한 텍스트를 번역한다.
4. 캡처 이미지에서 원문 영역을 가리고 배경을 채운다.
5. 같은 위치에 번역문을 그려 번역 이미지를 만든다.
6. 원래 화면과 동일한 위치·크기로 이미지를 오버레이한다.
7. 아래 프로그램의 화면이 바뀌면 해당 이미지와 번역 표시를 갱신한다.

OCR과 번역 과정은 유지하면서 표시 방식을 변경하는 구상이다. 대상 프로그램의 텍스트나 UI 자체를 수정하는 기능은 아니다.

번역된 화면을 주 사용 화면으로 삼고, 기존 결과 창은 원문 확인·복사·수정·재번역을 위한 보조 창으로 두는 방향을 제안한다. 기본 표시 설정 변경은 구현 시 별도로 결정한다.

## 원문 제거와 배경 복원

캡처 이미지를 띄우는 것만으로 원문이 사라지지는 않는다. 번역문을 그리기 전에 원문 픽셀을 가리거나 제거해야 한다.

| 배경 | 가능한 접근 | 한계 |
| --- | --- | --- |
| 단색 UI | 글자 주변에서 배경색을 추정해 원문 영역 채우기 | 버튼 경계·아이콘·구분선까지 덮지 않도록 범위 조정 필요 |
| 그라데이션·단순한 무늬 | 주변 픽셀 보간이나 복사 등 일반 이미지 처리 | 배경에 따라 번짐·반복 무늬·이음새가 보일 수 있음 |
| 복잡한 사진·그림 | 인페인팅 알고리즘 또는 이미지 복원 모델 | 처리 시간과 메모리 비용이 들며 원래 배경을 정확히 복원한다고 보장할 수 없음 |

초기에는 모델 없이 단순한 배경부터 처리하고 실제 품질을 확인하는 방향을 제안한다. 복원이 어려운 영역의 표시 방식은 별도로 정한다. 예를 들어 해당 텍스트 영역만 가독성 있는 배경으로 덮는 대안을 둘 수 있다.

문단 전체 사각형을 일괄 덮으면 줄 사이의 배경이나 주변 UI까지 사라질 수 있다. 번역 단위는 문단을 유지하더라도, 원문 제거 범위는 줄별 위치 또는 더 정밀한 글자 마스크를 활용할 수 있도록 검토한다.

## macOS 기본 기능과 모델 도입 여부

- Core Graphics/AppKit으로 이미지 위에 색과 텍스트를 그릴 수 있고, Core Image로 필터·합성·사용자 정의 이미지 처리를 구성할 수 있다. 배경색 추정과 원문 제거 범위 결정은 앱에서 구현해야 한다.
- 사진 앱에는 Apple Intelligence의 Clean Up 기능이 있다. 다만 이번에 확인한 Apple 공개 문서에서는 이 기능을 다른 앱이 자동 호출할 수 있는 공개 API를 찾지 못했다. LineLens 설계는 해당 기능을 호출할 수 있다는 전제에 의존하지 않는다.
- 로컬 LLM은 이 표시 방식의 필수 구성 요소가 아니다. 텍스트 번역은 기존 Apple Translation을 유지할 수 있다.
- 복잡한 배경 복원이 필요하면 이미지 복원 전용 모델을 검토한다. 이 경우에도 로컬 실행이 가능하도록 구성할 수 있으며, 외부 서버 사용이 필수인 것은 아니다.
- 모델 도입 시에는 라이선스, 배포 크기, 지원 macOS·하드웨어, 메모리 사용량과 처리 지연을 확인해야 한다. 구체적인 모델은 아직 선정하지 않았고, 이번 구현에도 추가하지 않았다.

## 화면 동기화와 조작

클릭 통과는 입력 전달 문제를 해결하지만, 보이는 이미지가 실제 화면과 일치하는 것까지 보장하지는 않는다. 이전 캡처가 남은 상태에서 아래 프로그램의 버튼 위치가 바뀌면 사용자가 보고 누른 위치와 실제 동작이 어긋날 수 있다.

따라서 다음 처리가 중요하다.

- 화면 변화 감지와 OCR·번역 작업 주기를 분리한다. 현재의 기본 2초 갱신만으로 조작 중 화면 동기화가 충분하다고 가정하지 않는다.
- 클릭·스크롤·메뉴 열림·호버 등으로 내용이 변하면 오래된 번역 이미지를 빠르게 숨겨 실제 화면을 보여주고, 새 번역이 준비되면 다시 표시하는 방식을 검토한다.
- 화면 변화 감지는 오버레이가 제외된 캡처를 기준으로 한다. 클릭 통과 오버레이가 직접 마우스 이벤트를 받는다고 가정하지 않는다.
- 캡처 이미지와 OCR 좌표·번역 결과를 같은 화면 버전에 연결한다. 번역 중 화면이 바뀌면 이전 결과를 새 이미지에 적용하지 않는다.
- 창 이동·크기 변경·최소화·다른 앱 전환 시 표시 위치와 숨김 동작을 확인한다. 특히 영역 캡처는 그 위치에 보이는 화면이 대상이라는 기존 특성을 고려한다.
- 새 화면에서도 내용과 위치가 유지된 텍스트는 번역 캐시를 활용하되, 더 이상 존재하지 않는 영역에는 이전 번역을 남기지 않는다.

## 번역문 배치

- 원래 텍스트의 위치·글자 크기·색상·정렬을 최대한 참고한다. OCR만으로 원래 폰트와 굵기를 정확하게 알아낸다고 가정하지 않는다.
- 번역문 길이가 늘어나면 줄바꿈과 글자 크기를 조정한다. 지나친 축소로 읽기 어려워지는 경우의 처리 기준이 필요하다.
- 제목, 설명, 메뉴 항목이 잘못 묶이거나 서로 겹치지 않도록 한다.
- Retina 배율과 화면 좌표 변환을 유지해 원문 제거 영역과 번역문이 실제 위치에 맞도록 한다.

## 제안하는 진행 순서

1. 기존 OCR·번역을 유지하고, 캡처 이미지를 오버레이에 표시하는 경로를 구성한다.
2. 단색 배경의 원문 제거와 번역문 배치를 구현해 정적인 화면에서 품질을 확인한다.
3. 오래된 이미지 숨김, 화면 버전 관리, 창 추적을 연결해 실제 조작 중 사용성을 확인한다. 이 처리가 갖춰지기 전에는 클릭 통과만으로 실사용에 문제가 없다고 판단하지 않는다.
4. 결과 창을 보조 도구로 사용하는 흐름과 기본 표시 설정을 검토한다.
5. 사진·그라데이션·무늬 화면에서 품질을 평가한 뒤 일반 이미지 처리 확장 또는 로컬 이미지 복원 모델 도입을 결정한다.

## 구현 후 확인할 항목

- 밝은 배경·어두운 배경에서 원문이 남지 않고 번역문을 읽을 수 있는가.
- 버튼 경계·구분선·아이콘과 텍스트 주변의 이미지가 보존되는가.
- 번역문이 길어져도 인접한 조작 요소와 겹치지 않는가.
- 오버레이가 켜진 상태에서 실제 프로그램의 클릭·스크롤·드래그·호버·키보드 조작이 가능한가.
- 화면이 바뀌면 이전 이미지가 적절히 숨겨지며, 느리게 도착한 번역이 잘못된 화면에 표시되지 않는가.
- 창 이동·크기 변경·최소화·다중 모니터와 Retina 환경에서 위치가 맞는가.
- 오버레이 자체가 다시 OCR되지 않는가.
- 반복 갱신 중 깜빡임, CPU·GPU 사용량, 메모리 사용량이 사용을 방해하지 않는가.
