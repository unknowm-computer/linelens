# 번역 오버레이의 스크롤 전환 개선 계획

작성일: 2026-11-03

상태: 후속 계획. 이 문서의 이동 추적·영역 분리·전환 효과는 아직 구현하지 않았다.

## 현재 상태와 목표

1차 구현은 ScreenCaptureKit의 실시간 배경과 문구별 번역 레이어를 분리해 입력 반응을 개선했다. 사용자는 현재 반응속도는 사용할 만한 수준이며 특히 스크롤 사용성이 좋아졌다고 평가했다. 다음 목표는 이 반응성을 유지하면서 스크롤 중 원문과 번역 조각이 어긋나는 중간 화면을 줄이는 것이다.

현재 배경은 최대 30fps로 캡처를 요청하지만, 변경 감지용 픽셀 분석은 최대 5fps로 제한한다. 이는 요청·분석 주기이며 실제 표시 속도나 지연을 보장하는 수치는 아니다. 번역 조각의 위치는 새 OCR 결과를 받아 갱신하므로 배경이 먼저 움직이고 이전 번역이 잠시 남거나 새 위치로 튀어 보일 수 있다.

`OverlayInteractionMonitor`는 현재 클릭·스크롤을 추가 인식 요청에 사용한다. 스크롤 이동량, 제스처 단계와 관성 상태를 번역 레이어의 위치에 반영하지 않는다. `TranslationOverlayController`도 기존 조각의 위치를 실제 스크롤에 맞춰 연속 이동시키는 기능은 없다.

## 우선순위 1: 기존 번역 조각의 이동 추적

- 같은 문구가 화면 안에서 이동한 경우에는 OCR·번역을 다시 기다리지 않고 기존 번역 조각의 위치를 먼저 옮긴다.
- 휠·트랙패드 입력은 스크롤 시작과 방향을 파악하는 보조 정보로 사용한다. 앱별 스크롤 가속·확대 배율·관성·끝부분 튕김 때문에 입력 델타를 화면 픽셀 이동량으로 그대로 적용하지 않는다.
- 오버레이가 제외된 연속 캡처에서 실제 콘텐츠의 이동량을 추정하고 보정한다. Vision의 `VNTranslationalImageRegistrationRequest` 또는 연속 추적 API를 우선 검토한다.
- 저해상도 이미지 또는 선택한 영역으로 처리 부하를 제한한다. 추적용 분석 주기는 현재 OCR 분석 주기와 별도로 설계하고, UI 스레드를 막지 않는지 실측한다.
- 이동 추정치가 원문 영역과 맞는지 검증하고, 화면 밖으로 나간 번역은 해당 영역 경계에서 잘라낸다. 작은 오차가 계속 누적되지 않도록 새 인식 결과로 기준점을 갱신한다.

## 우선순위 2: 고정 영역과 스크롤 영역 분리

- 상단 메뉴·사이드바·고정 헤더는 유지하고, 실제로 움직이는 본문 번역만 이동시킨다.
- 프로그램이 제공하는 접근성 정보와 캡처의 움직임 분포를 영역 구분의 후보로 사용한다. 모든 앱에서 접근성 정보를 제공한다고 가정하지 않는다.
- 여러 스크롤 영역, 고정 헤더가 바뀌는 화면, 독립적으로 움직이는 영상이 섞인 경우에는 영역별로 판단한다. 하나의 전체 화면 이동량을 무조건 적용하지 않는다.
- 첫 구현은 단일 본문 스크롤부터 검증하고, 신뢰할 수 없는 영역에는 기존 OCR 갱신 경로를 사용한다.

## 우선순위 3: 새 영역의 갱신과 교체 효과

- 이동해서 계속 보이는 문구는 기존 번역을 재사용하고, 새로 들어온 영역·실제 내용이 바뀐 문구만 인식·번역한다.
- 같은 문구의 원문 가림과 번역 조각을 함께 교체한다. 오래된 좌표의 가림과 새 번역이 따로 나타나는 상태를 줄인다.
- 위치 추적을 먼저 안정화한 뒤 문구별 짧은 페이드를 검토한다. 초기 실험값은 약 80~120ms이며 확정된 설정값은 아니다.
- 전체 화면을 교차 페이드해 글자가 이중으로 보이거나 클릭 결과가 늦게 보이는 상태를 피한다. 변경 없는 문구에는 전환 효과를 반복 적용하지 않는다.
- 실시간 화면 표시를 끈 경우와 자동 갱신을 끈 경우에는 현재의 이전 번역 화면 유지 동작을 보존한다.

## 추적 실패와 화면 버전 관리

- 빠른 페이지 전환, 큰 점프, 창 크기 변경, 추적할 특징이 부족한 화면은 연속 스크롤로 처리하지 않는다. 기존 재인식 경로로 전환한다.
- 추적 결과에는 대상·캡처 크기·기준 프레임 버전을 연결한다. 늦게 도착한 추적·OCR·번역이 새 대상이나 다른 레이아웃을 덮지 않도록 한다.
- `NSEvent.phase`와 `momentumPhase`를 함께 참고한다. 일반 휠처럼 단계 정보가 없는 장치도 처리한다. 손을 뗀 순간을 관성 스크롤 종료로 가정하지 않는다.
- 스크롤 중에도 새 영역의 OCR과 번역은 병행하고, 관성이 끝나면 최종 위치를 보정한다.
- 추적 실패 때 오래된 번역을 잠시 유지할지, 해당 조각만 해제할지는 실제 화면에서 비교 후 결정한다. 원문 노출·잔상·지연 사이의 차이를 검증하며 전체 오버레이를 반복 숨기는 동작을 기본으로 삼지 않는다.

## 관련 코드와 예상 역할

| 파일 | 후속 역할 |
| --- | --- |
| `Services/OverlayInteractionMonitor.swift` | 이동 델타·스크롤 단계·관성 정보 전달 |
| `Services/LiveCaptureSession.swift` | 추적용 프레임 전달과 처리 주기 분리 |
| `Services/ImageOverlaySession.swift` | 추적 기준 프레임·영역·버전 관리 |
| `Services/OverlayFrameMatcher.swift` | 이동 후 원문 영역 일치 검증 |
| `Windows/TranslationOverlayController.swift` | 영역별 레이어 이동·클리핑·문구 교체 |
| `LineLensCore/TextSnapshot.swift` | 이동한 문구의 식별자·번역 재사용 |
| `Services/OCRService.swift` | 새 노출 영역과 변경 문구의 부분 인식 |

경로는 `Sources/LineLens/` 기준이며 `LineLensCore/TextSnapshot.swift`는 `Sources/` 기준이다. 이동 추적 계산은 필요하면 별도 서비스로 분리한다.

## 확인 기준

- 느린 스크롤·빠른 스크롤·관성 스크롤·방향 반전에서 번역이 콘텐츠와 같은 방향·거리로 이동하는가.
- 메뉴·사이드바·고정 헤더는 움직이지 않고 해당 본문의 번역만 이동하는가.
- 화면 밖 문구와 새 노출 영역에서 잔상·이중 글자·가림 위치 불일치가 줄어드는가.
- 페이지 점프·창 이동·크기 변경·일시정지·대상 변경 때 잘못된 이동량을 적용하지 않는가.
- 클릭 통과와 현재의 빠른 배경 표시가 유지되는가.
- 추적 성공률, 위치 오차, 스크롤 종료 후 안정화 시간, CPU·GPU·메모리 사용량을 기존 방식과 비교한다. 성능 개선 수치는 아직 측정하지 않았다.
