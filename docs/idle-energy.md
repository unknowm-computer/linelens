# 사용하지 않을 때의 자원 수명

인식 대상이 없고 모든 창을 닫은 상태에서는 기능별 주기 작업과 숨은 화면을 유지하지 않는다.

- 캡처 스트림, OCR·번역 작업, 갱신·오버레이 타이머와 입력 감시는 기존 중단 경로를 유지한다.
- 결과 화면은 처음 앱을 실행할 때 만들지 않는다. 결과 창을 열거나 인식을 시작할 때 만든다.
- 인식 대상이 있는 동안에는 숨은 결과 화면의 `translationTask`를 유지해 화면 위 번역이 계속 동작한다. 인식을 해제하고 결과 창도 닫으면 화면과 호스트를 해제한다.
- 설정·권한 안내·창 선택 화면을 닫으면 SwiftUI 호스트도 제거한다. 선택 모드 진입 때 숨겨 두던 설정 화면도 닫아 알림 구독을 남기지 않는다. 결과·설정 창의 마지막 위치와 크기는 값으로 보관한다.
- OCR·번역 지원 언어 목록은 설정 또는 언어 팝오버를 열 때 조회한다. 같은 목록은 재사용하고 품질 선택이 달라지면 갱신한다. 화면을 닫으면 해당 조회 작업의 취소를 전달한다.
- 자동 업데이트 확인이 꺼진 시작 상태에서는 Sparkle 컨트롤러를 생성하지 않는다. 수동 확인 또는 자동 확인 활성화 시 생성한다. 한 번 생성한 컨트롤러는 설치 중인 업데이트를 방해하지 않도록 앱 종료까지 재사용하며, 자동 확인이 켜져 있으면 기존 설정대로 예약한다.

메뉴 막대와 단축키를 위한 macOS 이벤트 처리는 계속 존재한다. 대기 부하를 줄이기 위해 별도 주기 진단 타이머나 에너지 감시 기능을 앱에 추가하지 않는다.

## 검증 (2026-11-03)

- 전체 테스트 95개(앱 71개·코어 24개) 통과. 초기 숨은 호스트 미생성, 대기 호스트 해제·재생성, 인식 중 숨은 번역 호스트 유지, 자동 확인 끄기·켜기에 따른 업데이트 초기화를 검증한다.
- 실제 설정 창을 닫고 다시 열어 설정·언어 목록이 복구되는 것을 확인했다. 인식 언어 목록에 영어·일본어·한국어가 표시됐다.
- 수동 업데이트 확인이 실제로 실행되어 ‘현재 최신 버전’ 안내가 나타나는 것을 확인했다. 자동 확인은 끄기를 유지했다.
- 영어 테스트 창을 선택해 번역하고 결과 창을 닫은 후 `Page 123`을 `Page 124`로 바꿨다. 결과 창을 다시 열어 원문·번역이 모두 124로 갱신된 것을 확인했다.
- 테스트 인식을 종료하고 새 프로세스를 창 없이 30초 관찰했다. CPU 평균은 반올림 시 0.000%, 최대 0.005%, interrupt wakeup은 4회, package wakeup은 0회였다. 이는 CPU·깨우기 측정이며 Activity Monitor의 ‘에너지 영향’ 점수는 아니다.
- 언어 목록 조회의 화면 수명 처리를 보완한 뒤 관련 17개 테스트도 통과했다.
- 이전에 보고된 에너지 영향 10 이상 구간을 동일 조건으로 재현하지 못했다. 위 수치로 장시간 사용 중 에너지 영향의 상한이나 개선 비율을 보장하지 않는다.

관련 코드는 `AppWindows`, `AppModel.loadLanguageOptionsIfNeeded()`, `AppUpdater`에 있다. 창을 닫은 대기 상태와 인식 중 숨은 창을 구분하는 동작을 유지한다.

[Apple 에너지 효율 가이드](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/BestPractices.html)는 사용하지 않을 때 불필요한 작업과 보이지 않는 화면 갱신을 중단하도록 권장한다.
