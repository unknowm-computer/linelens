# 툴팁·시스템 팝업의 번역 오버레이 처리 계획

작성일: 2026-11-03

‘브라우저 링크 주소 표시 영역 제외’를 켜면 브라우저 하단의 링크 주소 표시창과 겹친 영역만 오버레이에서 비운다. 다른 팝업을 구분하고 별도로 번역하는 작업은 후속 계획이다.

## 배경과 현재 동작

현재 프로그램 창을 대상으로 하는 캡처는 선택한 창을 기준으로 한다. 별도 창으로 표시되는 툴팁·팝업은 부모 창 캡처에 포함되지 않을 수 있다. 브라우저의 `title` 툴팁이나 alert도 구현에 따라 창 구성이 다르므로 이름만으로 구분하지 않고 실제 창 구성과 캡처 포함 여부를 확인해야 한다.

현재 번역은 대상 앱이 비활성 상태여도 유지한다. 다만 별도 창이 번역 영역에 실제로 겹치면 오버레이 전체를 숨긴다. 작은 툴팁 하나로 배경 번역이 모두 사라지는 현상도 이 조건에서 발생할 수 있다.

목표는 팝업을 원래 위치에서 즉시 볼 수 있게 하면서 나머지 번역을 유지하고, 필요한 팝업 내용만 별도로 번역하는 것이다.

## 유형별 처리 방향

| 유형 | 처리 방향 |
| --- | --- |
| 페이지 내부 HTML/CSS 툴팁·모달 | 같은 창 캡처에 포함되는 경우 기존 화면 변경 인식·번역 경로 사용 |
| 별도 창으로 뜨는 툴팁 | 겹친 부분의 부모 오버레이만 제외해 원래 툴팁을 즉시 표시. 툴팁이 유지되면 해당 내용만 별도 인식·번역 |
| 별도 창의 alert·대화상자·시트 | 원래 인식 대상을 보존하고 팝업을 임시 번역 대상으로 추가. 모달인 경우 팝업 번역을 우선 처리 |
| 관계가 확인되지 않은 다른 창 | 기존 가림 정책 유지. 같은 앱의 일반 문서 창을 팝업으로 간주하지 않음 |

같은 앱이 만든 창이라는 이유만으로 팝업으로 판단하지 않는다. 소속 프로세스, 부모·자식 관계, 접근성 역할과 창 정보 등을 함께 확인한다. 앱별로 제공하는 정보가 다르므로 분류가 불확실하면 원래 팝업이 보이는 기존 숨김 동작으로 처리한다.

## 공통 표시 원칙

- 팝업 번역이 준비되기 전에는 원래 팝업을 그대로 보여 준다. 부모 창의 번역이나 캡처 이미지가 팝업을 덮으면 안 된다.
- 확인된 팝업이 차지하는 부분만 부모 오버레이에서 제외하고, 그 밖의 번역은 유지한다. 팝업의 테두리·그림자·버튼이 잘리지 않도록 실제 표시 범위를 확인한다.
- 제외 영역은 번역 조각뿐 아니라 부모의 캡처 배경 레이어에도 함께 적용한다. 번역 글자만 숨기고 배경 이미지가 남아 팝업을 가리는 상태를 막는다.
- 팝업 번역은 원래 팝업 위의 별도 레이어 또는 오버레이로 표시한다. 클릭·스크롤·키보드 포커스는 원래 앱과 팝업이 받는다. 번역 오버레이는 `ignoresMouseEvents = true`를 유지하고 앱을 활성화하지 않는다.
- 표시·해제는 opacity 중심으로 처리한다. 기존 창을 숨기고 다시 띄우는 기본 확대·축소 효과를 추가하지 않는다.

## 툴팁의 처리 흐름

1. 툴팁의 등장과 부모 창과의 관계를 확인한다.
2. 부모 오버레이에서 툴팁과 겹친 영역을 즉시 제외한다. 나머지 부모 번역은 유지한다.
3. 툴팁이 잠깐 나타났다가 사라지는 경우에는 원문만 보여 준다. 유지되는 툴팁은 내용과 위치가 안정된 뒤 별도 인식을 요청한다. 대기 시간은 실사용 확인 후 정한다.
4. 현재 설정에 맞춰 앱 텍스트 읽기 또는 OCR을 사용하고, 번역문 텍스트 캐시를 확인한 뒤 필요한 문구만 번역한다.
5. 번역이 준비되면 현재 툴팁 위치에 표시한다. 이동·내용 변경 시 이전 결과가 맞는지 다시 확인한다.
6. 툴팁이 사라지면 진행 중인 작업과 팝업 번역 이미지·좌표를 폐기하고 부모 오버레이의 제외 영역을 해제한다. 늦게 도착한 번역을 뒤늦게 표시하지 않는다.

## alert·대화상자의 처리 흐름

1. 부모 창과 연결된 팝업을 확인하고 임시 번역 상태를 만든다. 사용자가 선택한 원래 인식 대상은 바꾸지 않는다.
2. 팝업 영역의 부모 오버레이를 제외해 원래 alert와 버튼을 즉시 사용할 수 있게 한다.
3. 모달 상태라면 부모 창의 반복 OCR·번역을 잠시 보류하고 팝업 번역을 우선한다. 일반 비모달 팝업은 부모 작업을 무조건 멈추지 않는다.
4. 팝업의 최신 화면을 인식하고 번역이 준비되면 팝업 위치에 표시한다. 캡처 범위에 포함시킬지 별도 캡처를 사용할지는 창 구성과 ScreenCaptureKit 지원 범위를 확인해 결정한다.
5. 팝업이 닫히면 팝업 캡처·인식·표시 작업을 정리한다. 부모 창을 최신 화면으로 다시 확인하고 번역을 갱신한다. 팝업 등장 전 이미지를 그대로 복원하지 않는다.

캡처나 분류·번역에 실패하면 원래 팝업이 보이는 상태를 유지한다. 원래 버튼과 시스템 UI를 가린 채 오래된 번역을 남기지 않는다.

## 상태·성능 관리

- 부모 인식 대상, 팝업 창 식별자, 등장 시점의 작업 버전과 캡처 기준을 연결한다. 창 식별자가 재사용되거나 팝업이 교체돼도 이전 응답을 적용하지 않는다.
- 여러 툴팁·중첩 대화상자는 창의 앞뒤 순서와 부모 관계를 확인한다. 여러 제외 영역이 겹치거나 부모 창 밖으로 나가는 경우도 처리한다.
- 부모와 팝업 모두 번역문 텍스트 캐시는 재사용할 수 있다. 원문 언어·목표 언어·번역 품질별 캐시 구분은 유지한다.
- 팝업 이미지·좌표·별도 캡처 세션은 사라질 때 정리한다. 인식 해제·일시정지·대상 변경 시 부모와 팝업 작업을 함께 취소한다.
- 대상이 없는 유휴 상태에서 팝업 감시용 타이머를 새로 돌리지 않는다. 활성 인식의 기존 창 확인 경로를 활용하고 조회·캡처의 중복을 줄인다.
- 별도 LLM이나 이미지 복원 모델 추가를 전제로 하지 않는다. 현재의 ScreenCaptureKit·앱 접근성 정보·Vision OCR·Apple Translation 경로를 활용한다.

## 구현 순서와 관련 코드

1. 창 구분과 제외 영역 계산을 분리하고, 확인된 팝업 영역만 부모 오버레이에서 제외한다.
2. 툴팁의 등장·유지·이동·소멸과 지연 응답 취소를 연결한다.
3. alert·대화상자의 임시 번역 상태와 종료 후 부모 화면 갱신을 연결한다.
4. 앱별 창 구성, 입력 통과, 화면 배율·다중 모니터와 처리 부하를 검증한다.

| 현재 코드 | 후속 역할 |
| --- | --- |
| `Sources/LineLens/Services/ScreenCaptureService.swift` | 창 목록·캡처 범위·가림 정보 제공. 팝업 분류 로직은 필요에 따라 별도 서비스로 분리 |
| `Sources/LineLens/Services/AccessibilityTextService.swift` | 팝업 관계·역할 및 보이는 텍스트 읽기 가능 여부 확인 |
| `Sources/LineLens/Windows/TranslationOverlayController.swift` | 배경과 번역 레이어의 공통 제외 영역, 팝업 번역 표시 |
| `Sources/LineLens/Services/ImageOverlaySession.swift` | 팝업별 캡처·인식·렌더링 버전과 취소 관리 |
| `Sources/LineLens/AppModel.swift` | 부모 대상 보존, 임시 팝업 상태와 작업 우선순위 연결 |

## 확인 기준

- `title` 툴팁 하나가 나타나도 배경 번역 전체가 사라지지 않는가.
- 번역 준비 전에도 팝업의 원문·테두리·버튼을 즉시 볼 수 있고 조작할 수 있는가.
- 툴팁 사이를 빠르게 이동하거나 바로 닫았을 때 오래된 번역이 다시 나타나지 않는가.
- alert·시트·중첩 대화상자를 닫으면 부모 창을 다시 선택하지 않아도 최신 번역으로 복귀하는가.
- 페이지 내부 HTML/CSS 팝업의 기존 인식 동작이 유지되는가.
- 같은 앱의 다른 일반 창이나 다른 앱 창을 팝업으로 오인하지 않는가.
- Retina 배율·음수 모니터 좌표·창 이동·일부 영역 선택에서도 제외 영역과 팝업 번역 위치가 맞는가.
- 인식 해제·일시정지 후 팝업 감시·타이머·캡처가 남지 않는가.

이 문서의 흐름과 기준은 구현 계획이며 검증 완료 기록이 아니다. 현재 구현과 스크롤·유휴 상태는 [번역 오버레이 문서](translated-image-overlay.md), 검증 범위는 [테스트 문서](manual-testing.md)를 참고한다.
