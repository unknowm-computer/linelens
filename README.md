# LineLens

화면의 특정 영역이나 프로그램 창에서 글자를 인식하고, 설정에 따라 번역문을 표시하는 macOS 앱.

## 실행

macOS 15 이상과 Swift 6 이상이 필요하다. 업데이트에는 SwiftPM으로 고정한 Sparkle 2.10.1을 사용한다. 최초 빌드 시 패키지 다운로드에 인터넷이 필요하다.
아래는 기존 서명 키를 보유한 Mac에서의 소스 빌드 절차다. 앱을 설치받는 사용자는 아래 배포·업데이트 절차를 따른다.

```sh
./scripts/setup-local-signing.sh # 서명 Mac의 기존 키 확인·전용 키체인 열기
./scripts/setup-sparkle.sh # 업데이트 서명 키 확인 (최초 설정 시 생성)
./scripts/build-app.sh
open dist/LineLens.app
```

- 최초 실행 시 화면 기록 권한 안내를 확인한다. 권한 적용에 재실행이 필요할 수 있다.
- 메뉴 막대에서 ‘화면 영역 선택’ 또는 ‘프로그램 창 직접 선택’을 실행한다. 결과 창의 ‘창 선택’ 버튼도 직접 선택을 시작한다.
- 직접 선택에서는 마우스를 올린 창에 테두리가 표시된다. 위쪽에서 ‘전체 창’ 또는 ‘창 내부 영역’을 고른 뒤 원하는 창을 클릭한다. 내부 영역은 이어서 드래그로 지정한다.
- 기본 영역 선택 단축키는 `Control + Option + L`이다. 직접 선택은 화면 위 ‘취소’ 또는 메뉴의 ‘선택 취소’로 취소하며, 인식 해제는 메뉴에서 한다. Escape는 가로채지 않는다.
- 창이 화면에 보이지 않으면 먼저 표시한 뒤 선택한다. ‘목록에서 선택’ 버튼 또는 메뉴의 ‘프로그램 창 목록에서 선택’도 사용할 수 있다.
- 설정에서 자동 번역을 켜고 원문·목표 언어를 선택한다. 새 설정의 기본값은 번역 켜기, 자동 갱신 2초, 번역 화면 표시다. 기존에 저장한 표시·언어 설정은 유지한다.
- 개발·배포용 앱 모두 같은 자체 서명 인증서를 사용한다. 개인 키는 서명하는 Mac의 저장소 밖 전용 키체인에 보관한다. 서명된 앱은 다른 Mac에도 배포할 수 있다. Apple 개발자 계정이나 공증은 사용하지 않는다.
- 기존 임시 서명에서 고정 서명으로 전환할 때는 화면 기록 재승인이 한 번 필요할 수 있다. 이후 코드 변경 시에도 같은 서명 신원을 유지한다.
- 고정 서명 설정이 없거나 인증서가 달라지면 빌드를 중단하고 기존 앱을 보존한다. 임시 서명으로 자동 전환하지 않는다.
- 배포 인증서의 공개 지문과 Bundle ID는 `Resources/SigningIdentity.plist`에 고정한다. 다른 Mac에서 설정 스크립트를 실행해 새 인증서를 만들거나 다른 인증서로 서명한 배포본을 만드는 것을 차단한다. 설치받는 Mac에서는 설정 스크립트를 실행하지 않는다.
- `CODE_SIGN_IDENTITY`와 선택적인 `CODE_SIGN_KEYCHAIN`도 고정된 인증서에 일치해야 한다. 인증서를 의도적으로 교체할 때는 공개 지문 설정도 변경해야 하며, 기존 앱 교체에는 `ALLOW_SIGNING_IDENTITY_CHANGE=1`이 필요하다. 인증서 교체 시 화면 기록 재승인이 필요할 수 있다.
- Xcode에서 소스를 열려면 `Package.swift`를 연다. `.app` 번들은 위 스크립트로 만든다.

## 다른 Mac에 배포하고 업데이트하기

서명 키를 보유한 Mac에서 다음 명령으로 배포 파일을 만든다. 버전과 빌드 번호는 서명 전에 앱에 반영하며 소스의 `Info.plist`는 변경하지 않는다.

```sh
./scripts/package-release.sh 0.1.2 3
```

결과는 `dist/releases/0.1.2/LineLens-0.1.2-universal.zip`이다. Apple Silicon·Intel 통합 앱과 설치 안내가 들어 있으며, ZIP의 SHA-256 체크섬과 서명된 `appcast.xml`도 함께 생성한다. 개인 키·키체인·비밀번호·개발 스크립트는 배포 파일에 포함하지 않는다. ZIP을 다시 압축 해제해 모든 아키텍처의 코드 서명, 업데이트 메타데이터와 EdDSA 서명을 검증한 후 결과를 확정한다. 이미 생성된 버전은 덮어쓰지 않는다.

다음 버전은 빌드 번호를 올리고, 가능하면 이전 배포본의 앱을 지정해 업데이트 서명 호환성을 확인한다.

```sh
./scripts/package-release.sh 0.1.3 4 --previous-app /path/to/previous/LineLens.app
# 이미 만들어진 두 앱만 검증할 때:
./scripts/verify-update.sh /path/to/previous/LineLens.app /path/to/update/LineLens.app
```

설치받는 사용자는 ZIP을 풀어 `LineLens.app`을 응용 프로그램 폴더에 설치하고, 최초 한 번 화면 기록을 허용한다. Sparkle가 포함된 버전부터 메뉴의 ‘업데이트 확인…’으로 새 버전을 내려받아 설치·재실행한다. 업데이트 서버가 게시되어 있어야 하며, 기존 0.1.1 이하는 새 ZIP으로 한 번 수동 교체해야 한다. 일반 업데이트에서는 화면 기록 항목을 삭제하거나 권한을 초기화하지 않는다. 개발 도구·서명 키체인은 필요 없다. [설치 안내](docs/distribution-install.txt)를 참고한다.

업데이트 주소는 현재 저장소의 **공개 GitHub Releases**를 기준으로 준비했다. 저장소·릴리스가 비공개이거나 아직 게시되지 않았다면 업데이트 확인은 실패한다. 이번 설정은 외부 게시를 수행하지 않는다. ZIP과 `appcast.xml` 게시, 별도 HTTPS 서버 설정, 키 백업 절차는 [Sparkle 배포 문서](docs/sparkle-updates.md)를 참고한다.

자체 서명은 Apple의 공증을 대신하지 않아 설치·업데이트 시 macOS의 실행 허용이 필요할 수 있다. 이 실행 확인은 화면 기록 승인과 별개다. 권한 유지는 같은 서명 신원으로 앱을 교체하는 방식이며, 다른 Mac에서의 실제 승인 유지와 Intel 하드웨어 실행은 별도 검증이 필요하다. 설치·업데이트 검증 절차는 [권한·서명 문서](docs/screen-permission.md)에 정리한다.

## 현재 구현

- 메뉴 막대 앱, 사용자 지정 전역 단축키, 설정 저장
- 취소 전까지 유지되는 화면 영역·프로그램 창·창 내부 영역 선택
- 화면에서 창을 직접 클릭해 선택, 마우스 아래 창 테두리 표시, 목록 선택 전환
- 일반 창과 떠 있는 프로그램 창 선택, 취소 시 기존 대상 유지
- 영역 이동·크기 변경, 수동·자동 갱신, 일시정지·재개
- Vision 빠른·정확한 OCR 선택, 문단 묶기, 동일 이미지 OCR 생략
- 변경된 타일을 기존 문단 범위까지 확장해 해당 영역만 OCR, 큰 화면 변화는 전체 인식
- 접근성 API로 프로그램 창의 텍스트 직접 읽기, 미지원 앱·이미지·권한 없음은 OCR 전환
- 자동 모드에서 하나의 SCStream 세션 유지, 변경 없는 화면의 결과·번역·갱신 시각 보존
- 배경 변화와 OCR 좌표 오차에 기존 문단을 재사용하고, 변경된 글자만 새로 번역
- Apple 로컬 번역의 속도·품질 선택(macOS 26.4 이상), 언어 지원 확인, 모델 다운로드 안내, 품질별 번역 캐시
- 원문·번역 결과 창, 클릭이 통과하는 캡처 이미지 기반 번역 오버레이
- 줄별 배경색·글자색 추정, 작은 번역 이미지 조각 캐시와 Core Animation 레이어 갱신
- 실시간 배경 표시와 OCR·번역 갱신 분리, 이전 번역 화면 유지 모드 선택
- 원문 수정·재번역, 원문·번역 복사, 결과 창 고정
- Sparkle 업데이트 확인 메뉴, 자동 확인 설정, EdDSA로 서명한 ZIP·appcast 생성

실제 화면 권한, 번역 모델 다운로드 및 다중 모니터 등 수동 검증 항목은 [수동 테스트 문서](docs/manual-testing.md)를 참고한다.

권한 확인은 실제 ScreenCaptureKit 접근으로 판단한다. CoreGraphics의 사전 확인값만으로 캡처를 차단하지 않으며, 권한 거부와 그 외 화면 접근 오류를 구분한다.

### 화면 기록 승인이 적용되지 않을 때

설정에서 LineLens가 켜져 있어도 이전 빌드의 서명이 저장되어 있으면 접근이 거부될 수 있다. 앱의 ‘권한 연결 초기화’ → ‘앱 다시 실행’ 후 시스템 안내에서 현재 앱을 다시 허용한다. 터미널에서는 다음 명령으로 같은 복구를 수행한다.

```sh
./scripts/reset-screen-permission.sh --relaunch
```

이 명령은 LineLens의 `ScreenCapture` 승인만 초기화한다. 다른 앱이나 마이크·손쉬운 사용 등의 권한은 변경하지 않는다. 초기화는 권한 허용을 대신하지 않으므로 사용자가 시스템 창에서 승인해야 한다.

빌드 스크립트는 별도 폴더에서 서명·검증한 앱을 교체하며, 실행 중인 기존 앱 파일에 덮어쓰지 않는다. 동일한 빌드는 기존 앱을 보존한다. 새 빌드가 기존 앱의 서명 요구조건을 만족하는지도 확인한다. 서명 설정과 실제 검증 기록은 [권한·서명 문서](docs/screen-permission.md)를 참고한다.

```sh
swift test
# xcode-select가 Command Line Tools를 가리키는 경우:
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun swift test
```

### 번역 화면 사용

설정의 ‘결과 표시’를 ‘번역 화면’, ‘화면 위 번역’을 ‘이미지 속 글자 바꾸기’로 선택하고 자동 번역을 켠다. 결과 창은 메뉴의 ‘결과 창 보기’에서 원문 확인·복사·수정용으로 열 수 있다. 인식 결과 창의 번역 토글 옆 ‘언어’ 버튼에서는 ‘인식 언어’와 ‘목표 언어’를 선택한다. 인식 언어를 고르면 OCR 언어와 번역 원문 언어에 함께 적용하며, 자동 감지를 고르면 둘 다 자동으로 전환한다. 설정 창과 같은 값을 공유하고 저장한다. 설정 창에서는 두 언어를 따로 지정할 수 있고, 서로 다르게 지정한 경우 결과 창은 ‘설정에서 개별 지정’으로 표시해 기존 값을 보존한다.

번역 화면은 클릭·스크롤·드래그를 아래 프로그램으로 통과시킨다. 기본으로 켜진 ‘실시간 화면 표시’에서는 ScreenCaptureKit의 IOSurface를 배경 레이어로 전달하고, 작은 번역 이미지 조각을 별도 레이어에 표시한다. 배경은 최대 30fps로 요청하며 변경 감지용 픽셀 분석은 최대 5fps로 분리한다. 실제 속도는 기기·대상 화면·처리 부하에 따라 달라진다. 매번 화면 전체를 CPU로 합성하지 않고 변경된 문구의 조각만 다시 만든다.

OCR은 변경된 64px 타일을 이전 문단 전체 범위까지 확장해 해당 부분만 인식한다. 변경 영역이 많거나 화면의 45%를 넘으면 전체를 인식한다. 번역 중에도 OCR을 계속하며, 새 레이아웃은 번역 완료를 기다리지 않고 표시한다. 번역 대기 문구는 …로 가리고 도착한 번역을 문구별로 반영한다. 클릭·스크롤 뒤에도 새 인식을 요청한다. 새 위치에 나타난 원문은 OCR이 끝나기 전 잠깐 보일 수 있고, 이동 중에는 이전 번역 조각이 잠시 남을 수 있다.

‘실시간 화면 표시’를 끄면 다음 OCR·조각 생성이 끝날 때까지 이전 번역 화면을 유지한다. 이 모드는 원문 노출을 줄이지만 클릭 결과의 표시도 늦어진다. 자동 갱신을 끄면 두 모드 모두 마지막 번역 화면을 유지하며 수동 새로고침으로 갱신한다. 전체 창의 위쪽 32pt는 제목 표시줄과 시스템 녹화 표시를 위해 원래 화면을 유지한다.

설정의 기본값은 ‘텍스트 읽기: 자동 · 앱 텍스트 우선’, ‘OCR 모드: 빠른 OCR’, ‘번역 처리: 속도 우선’이다. 앱 텍스트 우선은 프로그램 창에만 적용하며, 설정의 권한 항목에서 접근성 권한을 사용자가 허용해야 한다. 텍스트가 제공되지 않는 앱·게임·이미지나 권한이 없는 경우에는 OCR을 사용한다. 앱이 제공하는 텍스트 상자는 실제 글자보다 넓을 수 있으므로 위치가 부정확하면 ‘화면 OCR’을 선택한다.

빠른 OCR의 지원 언어는 실행 환경에서 확인하며 영어 등 일부 언어로 제한된다. 미지원 언어를 지정하거나 빠른 결과가 비어 있거나 신뢰도가 낮으면 정확한 OCR을 사용한다. 자동 감지에서 혼합 문자 일부를 놓칠 수 있으므로 한국어·일본어 화면은 OCR 언어를 지정하거나 정확한 OCR을 선택한다. 번역 품질 선택은 Apple Translation의 lowLatency/highFidelity 전략을 사용하며 macOS 26.4 미만에서는 시스템 기본 번역으로 처리한다. 품질 모드의 지원 언어·모델은 속도 모드와 다를 수 있고 최초 다운로드가 필요할 수 있다.

번역 끄기·인식 해제·일시정지·대상 변경 때는 번역 화면을 해제한다. 다른 창이나 메뉴가 대상 창을 덮거나 대상 창이 최소화된 경우에도 번역 이미지를 숨겨 실제 프로그램 조작을 방해하지 않도록 한다.

복잡한 배경에서는 원문 영역을 주변에서 추정한 단색으로 덮는다. 번역문은 원래 영역 안에서 줄바꿈·크기 조정하며, 최소 크기에서도 넘치는 내용은 생략될 수 있다. 전체 내용은 결과 창에서 확인한다. 자세한 구현 범위는 [번역 오버레이 문서](docs/translated-image-overlay.md)를 참고한다.

### 다음 작업: 스크롤 전환 자연화

현재는 배경 화면과 번역 조각의 갱신 시점 차이로 스크롤 중 잔상이나 위치 어긋남이 보일 수 있다. 기존 번역의 이동 추적 → 고정 영역·스크롤 영역 분리 → 새 문구의 부분 교체와 짧은 전환 효과 순서로 검토한다. 이 기능은 아직 구현하지 않았다. [스크롤 전환 개선 계획](docs/scroll-overlay-smoothing.md)에 원인, 구현 순서, 실패 시 처리와 검증 기준을 정리한다.

아래는 앱의 기능 방향과 구현 범위다.

## 기본 방향

- Swift 기반 네이티브 앱으로 개발하며, 최소 지원 버전은 macOS 15로 계획한다.
- 메뉴 막대와 전역 단축키로 실행한다.
- OCR은 Apple Vision, 번역은 Apple Translation 프레임워크를 사용한다.
- OCR과 번역은 모두 로컬에서 처리한다. 번역 언어 모델의 최초 다운로드에는 인터넷이 필요하며, 설치 후에는 지원 언어 조합을 오프라인에서 사용할 수 있다.
- 별도 번역 API 키나 외부 번역 서버를 사용하지 않는다.

## 인식 대상 선택

| 방식 | 동작 |
| --- | --- |
| 화면 영역 | 화면에서 드래그한 고정 영역을 인식한다. 다른 창이 덮으면 그 위치에 보이는 내용이 대상이 된다. |
| 프로그램 창 | 앱과 대상 창을 선택해 인식하며, 창 이동에 맞춰 번역 표시도 따라가도록 구현한다. |
| 창 내부 영역 | 선택한 창의 일부 영역만 인식한다. 대사창이나 문서 본문 등에 활용한다. |

## 유지 및 갱신

- 선택 영역과 대상 창은 1회 캡처 후 해제하지 않고, 사용자가 취소할 때까지 유지한다.
- 선택 취소와 고정된 인식 대상 해제는 메뉴 막대에서 제공한다. 창 직접 선택 중에는 화면 위 취소 버튼도 제공한다.
- 다른 프로그램의 조작과 충돌하지 않도록 Escape는 취소·해제에 사용하지 않는다.
- 해제 단축키는 기본으로 지정하지 않고, 필요한 경우 사용자가 설정에서 별도의 키 조합을 지정할 수 있도록 한다.
- 고정 영역은 이동하거나 크기를 변경할 수 있도록 한다.
- 갱신 방식은 자동 갱신과 버튼·단축키를 통한 수동 갱신을 선택하는 구상이다.
- 자동 갱신 시 변경된 내용을 감지하고 중복 OCR·번역을 줄인다.
- 자동 모드는 캡처 세션을 유지한 채 최신 프레임을 설정 간격으로 확인한다. 정지 화면에서는 처리 표시나 갱신 시각을 반복해서 바꾸지 않는다.
- 프로그램 창이 다른 앱 뒤에 있어도 인식은 유지한다. 최소화·닫힘 상태에서는 결과 갱신을 기다리고, 화면 위 번역 표시의 가시성은 별도로 제어한다.

## 결과 표시 및 설정

- 번역을 끄면 OCR 원문을 표시하고, 켜면 번역문을 함께 제공한다.
- 별도 결과 창 또는 원문 위치에 겹치는 번역 상자로 표시한다.
- 번역 상자는 원문을 가리거나 원문 옆에 표시하는 방식을 고려한다.
- 화면 위 번역 표시는 클릭이 통과하도록 하여 대상 프로그램을 조작할 수 있게 한다.
- OCR 언어, 원문 언어 자동 감지·수동 선택, 목표 언어를 설정한다.
- 원문·번역 복사, OCR 원문 수정과 재번역, 일시정지·재개 기능을 고려한다.
- 대상 창이 최소화되거나 다른 앱 뒤로 가면 번역 표시를 숨기는 동작을 계획한다.

## 구현 범위와 제약

- 화면 캡처는 ScreenCaptureKit, 설정·결과 화면은 SwiftUI, 영역 선택·오버레이 창은 AppKit을 활용한다.
- 화면 캡처 권한 안내와 번역 언어 모델 다운로드·실패 상태 처리가 필요하다.
- OCR 지원 언어와 번역 지원 언어는 별개이므로 실행 환경에서 각각 확인한다.
- 원문 위치 표시는 Vision의 텍스트 위치 정보를 이용하되, 좌표 변환과 창 추적은 앱에서 구현한다.
- 번역문 길이에 따른 줄바꿈·크기·겹침을 조정해야 한다. 대상 프로그램의 텍스트 자체를 변경하는 방식은 아니다.
- 다중 모니터, Retina 배율, 전체 화면 및 Spaces 전환은 별도 검증이 필요하다.
- 작은 글씨·장식체·복잡한 문서에서는 오인식이 생길 수 있으며, 연속 번역에는 처리 지연과 성능 제어가 필요하다.
- 단색 배경은 주변 색을 추정해 원문을 덮는다. 사진·무늬 배경의 자연스러운 인페인팅과 이미지 복원 모델은 포함하지 않는다.
